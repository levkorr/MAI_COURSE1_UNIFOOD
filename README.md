# Между парами

Прототип на Python + Flask для студентов МАИ.

## Запуск

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python app.py
```

Откройте http://127.0.0.1:5051.

### Как открыть локальный UniFood на телефоне

Подключите телефон и компьютер к одной сети Wi-Fi.

1. Остановите текущий локальный сервер через `Ctrl+C`. Затем из папки проекта запустите UniFood в PowerShell:

   ```powershell
   .\.venv\Scripts\python.exe -m flask --app app run --host 0.0.0.0 --port 5051
   ```

   Обычный запуск через `python app.py` слушает `127.0.0.1`, поэтому сайт доступен только на компьютере.
2. В другом окне PowerShell выполните `ipconfig`. Найдите **IPv4-адрес** активного адаптера Wi-Fi, например `192.168.1.42`.
3. В браузере телефона откройте `http://192.168.1.42:5051`, подставив свой IP.

Если страница не открывается, проверьте, что Wi-Fi не гостевой и брандмауэр Windows разрешает входящие подключения к Python в **частной сети**. Личный план, созданный на компьютере, на телефоне не появится, потому что у телефона своя кука. Общий счётчик будет одинаковым.

## SQLite на постоянном диске

Для одного экземпляра Flask задайте `REPORT_DB` абсолютным путём к файлу на постоянном томе. При первом развёртывании создайте пустую базу в уже существующем каталоге. Команда инициализации отказывается перезаписывать файл.

```powershell
$env:REPORT_DB = 'D:\app-data\reports.sqlite3'
.venv\Scripts\python -m database init $env:REPORT_DB
.venv\Scripts\python app.py
```

Если `REPORT_DB` задан, Flask требует существующий файл, доступный для записи. Без переменной локальный запуск использует `reports.sqlite3` рядом с `app.py`.

При переносе остановите прежний экземпляр, чтобы он завершил все записи. Укажите путь к прежней базе и выполните копирование в новый файл через SQLite Backup API. Для переноса используйте свободный путь на томе.

```powershell
$sourceDb = (Resolve-Path -LiteralPath '.\reports.sqlite3').Path
$env:REPORT_DB = 'D:\app-data\reports.sqlite3'
@'
from contextlib import closing
from pathlib import Path
import sqlite3
import sys

source, destination = map(Path, sys.argv[1:])
with closing(sqlite3.connect(source.as_uri() + '?mode=ro', uri=True)) as old:
    destination.touch(exist_ok=False)
    try:
        with closing(sqlite3.connect(destination)) as new:
            old.backup(new)
    except sqlite3.Error:
        destination.unlink()
        raise
'@ | .venv\Scripts\python - $sourceDb $env:REPORT_DB
```

После успешного копирования запустите Flask с заданным `REPORT_DB`. При последующих обновлениях используйте тот же том и путь. Сохраняйте прежний адрес сайта, чтобы браузер продолжал отправлять `mp-visitor` и открывать свой план.

## Загруженность

Изначально 0%, статус «Нет оценок»: это отсутствие данных, а не подтверждённое отсутствие людей. Нажмите место на карте → «Я здесь» → 0–5, 5–10, 10–15 или 15–20 человек → «Поделиться».

Оценки сохраняются в `reports.sqlite3` и учитываются 30 минут. Процент: среднее середин диапазонов / 20 × 100%, с округлением. 20 человек — условная шкала прототипа, не измеренная вместимость каждого заведения. Все свежие оценки участвуют в среднем; число сообщений не суммируется как число посетителей. После истечения оценок показатель возвращается к 0%. Старые сохранённые сообщения автоматически переносятся в историю оценок.

Интерфейс обновляется раз в минуту и сразу после отправки оценки. По умолчанию выбрано «Сейчас»: отображается примерное число посетителей по свежим оценкам. Без оценок число людей неизвестно. Цены и выдуманное время ожидания не отображаются.

При выборе времени включается режим планов: отображается число пользователей, выбравших это заведение на сегодня в интервале ±5 минут от выбранного времени (по Москве). Кнопка «Пойду сюда» сохраняет план, «Отменить план» удаляет его. Новый выбор заменяет предыдущий план на этот день; повторное нажатие не увеличивает число людей. Запись на прошедшее время запрещена. Планы хранятся отдельно от оценок в таблице `visit_plans` файла `reports.sqlite3`. Анонимный пользователь определяется cookie браузера: разные браузеры могут считаться разными людьми. Это число заявленных намерений, а не прогноз фактической посещаемости.

В интерфейсе планы относятся к текущему дню по Москве. Для прошедшего времени показывается сообщение «Это время уже прошло. Записаться нельзя.». Режим «Сейчас» показывает текущие оценки.

API: `GET /api/places` (сейчас), `GET /api/places?time=12:30&date=YYYY-MM-DD` (планы); `POST /api/check-ins` с JSON `place_id` и `people_range` (например, `"5-10"`); `POST /api/plans?date=YYYY-MM-DD` с JSON `place_id` и `time`; `DELETE /api/plans?date=YYYY-MM-DD` (отмена своего плана на выбранную дату). Дата должна быть сегодняшней или завтрашней по Москве; по умолчанию сегодня. Проверки: `python -m unittest discover -s tests -v`.

## Расписание МАИ

10:30–10:45, 12:15–13:00, 14:30–14:45, 16:15–16:30, 18:00–18:15. Время посещения с шагом 5 минут. Единый источник расписания и настроек вузов — `universities.py`.

## МГСУ

Добавлены перемены 09:50–10:00, 11:20–11:30 и 12:50–13:00 по запросу пользователя; расписание будет дополнено. При выборе МГСУ обновляются расписание, заведения, карта и начало маршрута. Используется основной кампус на Ярославском шоссе, 26 (адрес: https://press.mgsu.ru/contacts/, координаты из OpenStreetMap). Каталог — `places-cache-mgsu.json`, локальная карта — `static/neighborhood-mgsu.svg`. API принимает `university=mai` или `university=mgsu`; по умолчанию МАИ. Планы разных вузов считаются отдельно. Существующие планы при миграции относятся к МАИ.

Команда `python build_schematic.py --university mgsu` использует сохранённую выгрузку `.tools/mgsu-area.osm`. Другой файл можно передать через `--input`. При отсутствии выгрузки или геометрии кампуса команда завершится с ошибкой и сохранит существующую карту.

## Карта и заведения

Реальные заведения из OpenStreetMap. Каталог обновляется через Overpass с резервным официальным API, сохраняется в `places-cache.json`; при сбое используется сохранённый снимок. Сведения могут быть неполными или устаревшими. © OpenStreetMap contributors, ODbL: https://www.openstreetmap.org/copyright .

Приложение сразу отдаёт просроченный снимок и обновляет его в фоне. При неполной геометрии резервного XML или исчезновении ранее известного отношения из этого ответа приложение сохраняет предыдущий каталог. Для записи из скриптов используйте `places_source.read_snapshot` перед сверкой и `places_source.replace_catalogue` после неё. Конфликт версий означает, что каталог уже обновил другой процесс.

Локальная SVG-схема `static/neighborhood.svg` ограничена кругом радиусом 1 км от главного выхода ГУК зоны А (55.8104364, 37.4983111). Leaflet обеспечивает масштабирование и перемещение без внешних запросов тайлов или API-ключей. Повторная сборка: `python build_schematic.py` из сохранённого `osm-schematic.xml`.

Время пешком приблизительное: расстояние по прямой × 1.3 / 80 м/мин. Это не проверенный маршрут; в карточке есть ссылка на пеший маршрут в Яндекс Картах.

## Проверка OpenStreetMap MCP

Сверка каталога 25.11.2026 через подключённый MCP (`osm_query_bbox`, отдельно `amenity` и `shop`): все 34 записи совпали по названиям, координатам, категориям, адресам и расписаниям. Снимок обновлён в `places-cache.json`, предыдущий сохранён в `places-cache.before-audit.json`. Подробности и ограничения — `places-audit.json`, исходный ответ для выбранных категорий — `osm-places-audit-input.json`. В OSM отсутствуют полные адреса у 29 записей, часы работы у 14, дата проверки у 15; у «Взлёта» и «Теремка» указан `access=private`. Ещё 7 объектов без названия исключены существующим фильтром каталога. Совпадение с OSM не подтверждает фактическую работу заведений; зеркало обновляется ежедневно. `scripts/audit_places.py` воспроизводит сравнение из сохранённого ответа и обновляет снимок, но сам не запрашивает свежие данные MCP.

Исправленный локальный сервер: `.tools/osmmcp/osmmcp-fixed.exe`. Проверка подключения, списка инструментов и версии без внешних запросов: `python scripts/check_osmmcp.py --offline`. Полная проверка с поиском пяти кафе рядом с МАИ и выборкой по области: `python scripts/check_osmmcp.py`. Проверка работы дольше прежнего 30-секундного сбоя Windows: `python scripts/check_osmmcp.py --idle-seconds 35`.

Ответ поиска сохраняется в `.tools/osmmcp/nearby-mai.json`, журнал сервера — в `.tools/osmmcp/check-stderr.log`. Ошибка Overpass означает сбой поиска мест и не обязательно сбой самого MCP: проверка версии и геокодирование используют другие пути. Скрипт не обновляет каталог приложения `places-cache.json`.

Для МАИ настроено зеркало Европы `https://ovp.dresel.systems/api/interpreter`: оно использует европейскую выгрузку OSM с ежедневным обновлением, поэтому не подходит для поиска за пределами Европы. Основной публичный сервер `overpass-api.de` возвращал 502 из-за переполнения очереди; `maps.mail.ru` отвечал нестабильно. Поддерживается выбор сервера флагом `--overpass-endpoint`; без этого флага сборка использует глобальное зеркало VK Maps. При сетевых ошибках, 429, 502, 503 и 504 транспорт переключается на следующие серверы. Пустой успешный ответ регионального зеркала не вызывает переключение.

Исправлены также ложное завершение MCP на Windows из-за Unix-сигнала `0`, объединение альтернативных категорий через AND и потеря координат заведений, размеченных зданиями. Патч к исходникам `NERVsystems/osmmcp` ревизии `0916a0b` сохранён в `scripts/osmmcp-overpass.patch`; повторная сборка с тестами: `./scripts/build_osmmcp.ps1`. Применить запись подключения с резервной копией конфигурации: `.venv/Scripts/python scripts/configure_osmmcp.py --config "$env:USERPROFILE/.codex/config.toml"`. Уже работающий процесс MCP должен загрузить новую сборку при переподключении.

Сборка также применяет `scripts/osmmcp-bbox.patch`. Начиная с `0.1.2-bbox-complete`, успешный ответ `osm_query_bbox` содержит `complete: true`. Сообщение Overpass об ошибке, отсутствующий массив объектов или обрыв JSON останавливают сверку. [Инструкция по обновлению каталога](skills/osm-update-places/SKILL.md)
