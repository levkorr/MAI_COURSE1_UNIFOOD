# Сохранение данных при обновлении Flask

- Revision: 2
- Status: accepted
- Accepted revision: 2
- Решение пользователя: подтверждён отказ запуска при отсутствии файла по явно заданному пути. Для первого развёртывания требуется механизм создания пустой базы.
- Intent: `docs/feat-data-persistence/intent.md`, revision 2

## Требования и совместимость

- **R1 (O1).** Flask читает абсолютный путь к SQLite из переменной окружения `REPORT_DB` при запуске. Без переменной используется прежний `reports.sqlite3` рядом с `app.py`. При явно заданном пути сервер открывает существующий файл и сообщает об ошибке запуска, если файл отсутствует или недоступен для записи. При первом развёртывании отдельная команда создаёт SQLite с рабочей схемой и без записей оценок и планов. Команда завершается ошибкой, если файл уже существует, и сохраняет его содержимое.
- **R2 (O1, O2).** При переносе текущей установки SQLite создаёт согласованную копию существующей базы через API резервного копирования. Перед финальным копированием останавливают запись в прежнюю базу. Документация описывает первый запуск, перенос и последующие обновления с сохранением пути и тома. Приложение сохраняет историю оценок, планы и существующую совместимость со старой схемой, включая планы МАИ без поля `university`.
- **R3 (O3).** Сохраняются имя, формат и параметры cookie `mp-visitor`. UUID из действующей cookie сопоставляется с прежними планами. Смена версии при том же адресе сайта и сохранённой cookie оставляет доступными просмотр, замену и отмену своего плана. В браузере без cookie API выдаёт новый UUID, и чужой план не отображается как собственный.
- **R4 (O1, O3).** Сохраняются API и правила отображения. Оценка `5-10` даёт 7,5 человека, пока ей меньше 30 минут. План на 12:30 учитывается в интервале ±5 минут для выбранной даты и вуза. Эти сроки действуют и после обновления.

## Проверка

- Временная SQLite и фиксированное время. Через API записать оценку и план, перезапустить сервер с тем же путём и передать прежнюю cookie. Проверить сводку, счётчик планов, принадлежность плана, замену и отмену. Повторить чтение с новой cookie и проверить истечение срока оценки.
- Открыть копию базы предыдущей версии с заранее известными записями и проверить, что действующая cookie показывает прежний план. Проверить прежнюю схему из существующей логики миграции и повторное открытие базы без дублирования оценок.
- Проверить отказ запуска при отсутствующем файле по явно заданному пути, создание пустой базы отдельной командой и успешный запуск с ней. Повторная команда создания должна завершиться ошибкой с сохранением файла. Запустить обязательные проверки Basic из `docs/sdlc/project.md`.

SQLite подходит для одного экземпляра Flask с постоянным томом и сохраняет совместимость с текущим файлом. PostgreSQL имеет смысл, если нескольким экземплярам понадобится общая база. Избранное, каталог, аккаунты и смена домена вне объёма.
